神经网络-Chap.2

本系列神经网络课程根据Youtube上Andrej Karpathy的系列视频: Neural Networks: Zero to Hero整理而来.
应当可以作为对于LLM进行内部原理理解的入门视频之一.

这一节我们开始真正试着捣鼓出一些比较简单的模型. 依旧基于作者提供的一个GitHub库: https://github.com/karpathy/makemore

2.1 引子

我们的目的是捣鼓出来一个能生成一些很像名字的字符串的模型.
这个仓库的基本结构围绕着这个目的, 其结构非常简单:

makemore/
├── names.txt      # 【数据文件】约 32,000 个真实英文人名，每行一个名字
├── makemore.py    # 【源码】单文件包含了 Bigram / MLP / RNN / BoW / Transformer 5 种架构
├── README.md      # 项目说明与命令行运行指南
└── LICENSE        # MIT 开源协议

需要指出的是, 如果我们给了一个名字, 例如: adam. 我们其实能从这个名字里面获得的信息很多, like:

  • a有可能作为一个名字的起始字母
  • d有可能跟在a后面
  • a可能跟在ad后面
  • …
  • m有可能是名字的最后一个字母

为了更好地开始, 我们暂且不考虑过于复杂的信息, 如第二讲视频中所提及的, 我们这一节只是想做一个 ‘Bigram’ 模型. 即只根据前面一个字母来生成下一个字母.

2.2 探索相邻字符的关联

我们考虑从这段代码开始:

words = open('names.txt', 'r').read().splitlines()
for w in words:
    for ch1, ch2 in zip(w, w[1:]):
        print(ch1, ch2)

但就像我们上面所说的那样. 这样提取出的前后关联, 少了一步.
也就是开头的字母以及结尾的字母该怎么表示, 所以我们在字符串前后都加一个特殊字符.

words = open('names.txt', 'r').read().splitlines()
for w in words:
    chs = ['<S>'] + list(w) + ['<E>']
    for ch1, ch2 in zip(chs, chs[1:]):
        print(ch1, ch2)

现在我们用的是dictionary这个数据结构. 虽然这不算低效, 但确实不适合计算. 有没有更合适的方式来存储这种数据结构?
矩阵.

我们用矩阵的行作为第一个字母, 列作为第二个字母, 行列对应位置的数字作为计数值.
所以我们应该需要一个 28 * 28 的矩阵, 即26个字母 + 两个特殊字符.

我们直接用Pytorch来进行矩阵的创建, 存储更新:

import torch
N = torch.zeros((28, 28), dtype = torch.int32) # 存储计数, 所以只需要int类型即可
words = open('names.txt', 'r').read().splitlines()

chars = sorted(list(set(''.join(words))))
stoi = {s:i for i, s in enumerate(chars)} # a dictionary to convert letters to number
stoi['<S>'] = 26
stoi['<E>'] = 27

for w in words:
    chs = ['<S>'] + list(w) + ['<E>']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]

        N[ix1, ix2] += 1

for i in range(20):

        ix = torch.multinomial(p, num_samples = 1, replacement = True, generator = g).item()

        if ix == 0:

2.4 修复一个效率问题

上面的代码仅仅限制于 能跑 , 但是它的效率着实比较感人.
它的循环内部每一次都要算一遍概率, 这是很低效的做法.

更正常的做法, 是先把这个概率算出来, 再在循环内直接取用.
我们希望实现的步骤是: 每一行的数, 除以该行的总和.
为了更好的过渡到后面的模型类别, 我们更应该使用Pytorch相关的方法. 这里再介绍一个函数: torch.sum()

P = N.float()
P /= P.sum(1, keepdim = True)

这段代码得好好说说, 它挺复杂的.

第一行很简单, 我们把上面记录频次的这个27 * 27的数组完全赋值给了P.
第二行:

  • P.sum(1, keepdim = True): 在 P 这个 torch 类型对象上进行求和操作.
    • 第一个参数: 代表 消除 哪一维的结构. 0 代表行, 1 代表列. 这里消除了列的结构, 意味着把每一行的元素均加和.
    • 第二个参数 keepdim: 是否保留原维度结构. 本处原先是一个二维数组, keepdim 为 True 时, 会给出一个 27 * 1 的二维数组; 若该参数为 False, 则给出一个长度为 27 的一维数组.
  • P /= P.sum(1, keepdim = True): 用一个 27 * 27 的数组除以一个 27 * 1 的数组. 对于 torch 类型对象而言, 会将后者 以复制的形式 转化为一个 27 * 27 的数组, 并对应相除. (该机制称为广播机制 Broadcasting, 当两个数组其中一个维度相同, 而另一维度长度为 1 或缺失时会自动朝向缺失维度进行复制扩展)

所以我们通过这么简单的两行代码, 就获得了整个二维数组在整行上的概率分布.

这个Broadcasting, 请读者务必重视, 这玩意很容易写出bug来.

现在我们上面的循环写法可以变成:

for i in range(20):
    ix = 0
    out = []
    while True:
        p = P[ix]
        ix = torch.multinomial(p, num_samples = 1, replacement = True, generator = g).item()
        out.append(itos[ix])
        if ix == 0:
            break
    print(''.join(out))

2.5 评估我们刚刚的模型

通过刚刚的编写, 实际上我们已经成功训练出了一个模型, 尽管它十分简陋, 但确实, 它能够产生有效的输出了.

现在下一个问题是, 我们练出一个模型, 自然而然的, 就需要一个建模方案去 评估它 .
这件事, 在我们这个比较小的模型中, 是比较简单的:

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        prob = P[ch1, ch2]
        print(f'{ch1}{ch2}: {prob:.4f}')
output
.e: 0.0478
em: 0.0377
mm: 0.0253
ma: 0.3899
a.: 0.1960
.o: 0.0123
...

现在的问题是, 怎么把这一堆来自”训练数据集”的概率, 转化成一个能够作为评估模型好坏的数字?
从理论上来说, 对于 这一个训练数据组成的数据集 , 它的概率应当越接近100%越好. 所以我们如果希望结合上全部这一堆数据, 一个简单的方案是直接把它们全部相乘.

如果我们联系一下第一节中的内容, 应该能想到这个玩意: loss, 怎么把这一堆概率转变成loss?
我们想想上一节中loss的特征:

  • 永远是正数.
  • 越小(越接近0)越好.

那么现在这些概率值就存在问题: 它们的绝对值太小了, 离0太近. 直接相乘的话, 会直接超出计算机能够存储的最小值, 完蛋, 直接变成0了.(这里涉及到一些计算机组成原理中的知识, 对这方面没有了解的读者, 只需要了解到, 计算机能存储的小数是有最低下限的, 当超出这个限制, 就下溢直接存成0了)
在现有的主要解决方案中, 取log是一个比较常见的方案.

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        prob = P[ix1, ix2]
        logprob = torch.log(prob)
        print(f'{ch1}{ch2}: {prob:.4f} {logprob:.4f}')
output
.e: 0.0478 -3.0408
em: 0.0377 -3.2793
mm: 0.0253 -3.6772
ma: 0.3899 -0.9418
a.: 0.1960 -1.6299
.o: 0.0123 -4.3982
ol: 0.0780 -2.5508
...

现在数值够大了, 但是它们是负的. 这个简单, 取个负号.

而如果我们还记得高中关于对数的知识:

$$log(abc) = log(a) + log(b) + log(c)$$

所以我们只需要将这几个数字加在一块, 对总数据集数量取个平均就行了:

log_likelihood = 0.0
n = 0

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        prob = P[ix1, ix2]
        logprob = torch.log(prob)
        log_likelihood += logprob
        n += 1
        print(f'{ch1}{ch2}: {prob:.4f} {logprob:.4f}')

print(f'{log_likelihood=}')
nll = -log_likelihood
print(f'{nll=}')
print(f'{nll/n}')
output
log_likelihood=tensor(-559891.7500)
nll=tensor(559891.7500)
2.424102306365967

上面这个评估方式在现实中非常常用, 它叫做: 负似然对数(negative log likelihood)

但目前的代码还有一个小虫. 比如我们让这个评估方案凭据这个词语: andrejq

log_likelihood = 0.0
n = 0

for w in ["andrejq"]:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        prob = P[ix1, ix2]
        logprob = torch.log(prob)
        log_likelihood += logprob

        print(f'{ch1}{ch2}: {prob:.4f} {logprob:.4f}')

print(f'{log_likelihood=}')
nll = -log_likelihood
print(f'{nll=}')
print(f'{nll/n}')

这种情况是因为在我们的训练集合中, jq这种数据一次都没有出现. 所以在碰到jq之后, 结果直接变成 infinity 了.
这确实有些不符合直觉, 因为一个错误生成并不应当完全否定掉整个模型的可用性, 对吧.

所以, 有一种方案叫做: 模型平滑(Model Smoothing), 也就是在每种数据集的可能上都加上一定的 假样本数 :

P = (N+1).float()
...

2.6 使用神经网络的思路去训练Bigram模型

2.6.1 张量(tensor)

以上, 我们做了很多工作, 写了很多代码. 但是实质上我们的模型是基于我们最开始的计数程序而来的, 即这个counting program.
这实际上在训练更加大型的模型时, 是几乎无法复刻的. 因为更大的模型需要考虑的信息过多, 而我们刚刚在干的事情, 与我们第一节中手算导数的行为几乎无异.

所以我们现在要达到的目标是: 利用自动化程序, 让模型能够自动根据我们提供的数据集, 调整参数, 达到我们刚刚的模型效果.

第一步, 还是创造数据集, 只不过这一次, 我们不计数了:

# creare the training set of bigrams (x, y)
xs, ys = [], []

for w in words[:1]:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        xs.append(ix1)
        ys.append(ix2)

xs = torch.tensor(xs)
ys = torch.tensor(ys)
output
# xs(-emma)
tensor([0, 5, 13, 13, 1])

# ys(emma-)
tensor([5, 13, 13, 1, 0])

tensor , 中文译作 张量 , 其实可以直接当作编程中的多维数组来看. 上述代码中的xs, ys都是一维张量.
之所以要做这样一步转换, 是因为正常情况下, python本身的list放置数据的位置不够集中, 效率不够高. 而Pytorch提供的数据结构能够更高效的进行机器学习相关的计算.

这里额外提一嘴: 实际使用中尽可能使用 torch.tensor() , 而不要使用大写的版本( torch.Tensor() ), 二者区别在于小写的方法能够自动识别数据类型, 而大写的方法会默认采用float32类型.

2.6.2 转化张量, 并放入神经网络中进行计算

现在我们拿到了一维张量, 但正常来说, 我们不应该把这一维张量直接喂给模型.
正常而言, 每个字母的权重应该是一样的, 而这种一维张量, 显然, 字母越靠后, 数字越大.

这就得提到一个叫 one_hot 的函数. 它负责把一个一维张量转化为一个二维张量, 其中的每个一维张量的长度由参数决定, 其作用是让一维张量中对应的那个位置置值为1, 其余位置保持全0.

import torch.nn.functional as F
xenc = F.one_hot(xs, num_classes = 27).float()

2.6.4 loss

好, 现在问题就回到了我们熟悉的(?)地方.

我们首先得明确我们要的正确的概率在哪里, 事实上, 这一点在前面其实已经存起来了, 就在我们的 ys 里面(见2.6.1).
所以我们实际上关心的概率是:

但是显然, 我们要找到更加有效率能够访问这种正确概率的方式. 幸运的是, torch已经考虑到了这一点:

# create the dataset
xs, ys = [], []
for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        ix1 = stoi[ch1]
        ix2 = stoi[ch2]
        xs.append(ix1)
        ys.append(ix2)
xs = torch.tensor(xs)
ys = torch.tensor(ys)
num = xs.nelement()
print('number of examples: ', num)

# initialize the 'network'
g = torch.Generator().manual_seed(2147483647)
W = torch.randn((27, 27), generator=g, requires_grad=True)

# 3. 梯度下降主循环 (迭代 100 轮)
for k in range(100):

    # 前向传播 (Forward pass)
    xenc = F.one_hot(xs, num_classes=27).float()  # 将输入转为独热编码 [num, 27]
    logits = xenc @ W                             # 矩阵相乘预测对数频次 (log-counts)
    counts = logits.exp()                         # 取指数还原为正数频次 (等价于计数矩阵 N)
    probs = counts / counts.sum(1, keepdims=True) # 归一化得到下一字符的概率分布 (Softmax)
    loss = -probs[torch.arange(num), ys].log().mean() # 计算平均负对数似然损失 (NLL Loss)
    print(loss.item())

    # 反向传播 (Backward pass)
    W.grad = None                                 # 梯度清零 (设为 None 比填 0 更高效)
    loss.backward()

    # 更新参数 (Update)
    W.data += -50 * W.grad

2.6.7 Regularization

我们在前面提到了一个叫做Model Smoothing的事情(见2.5节). 在这里我们怎么实现它?
我们可以做这种修改:

# original
loss = -probs[torch.arange(num), ys].log().mean() # 计算平均负对数似然损失 (NLL Loss)
# to
loss = -probs[torch.arange(num), ys].log().mean() + 0.01*(W**2).mean()

我们在loss上加了个小尾巴, 理解一下这个式子, 我们会发现这个小尾巴只有当W这个张量全为0的时候, 才能不增加loss.

W这个张量全0意味着什么?
后面乘法乘出来的概率矩阵全是相同的数, 对吧. 其实就是完全平均分布(每个字母取的概率均等)

所以, 我们后面加这么个小尾巴, 本质上就在尝试把模型权重往平均拉平. (W**2) 前面那个参数越大, 模型越平滑.

这个事情, 在人工智能领域有个名字, 叫 Regularization .

2.6.8 用我们的模型生成几个名字

# 使用训练好的神经网络权重 W 抽样生成 5 个名字
g = torch.Generator().manual_seed(2147483647)

for i in range(5):
    out = []
    ix = 0  # 从起始符 '.' (编号 0) 开始
    while True:
        # 1. 将当前字符编号 ix 转为 [1, 27] 的独热向量，通过神经网络前向传播算出概率 p
        xenc = F.one_hot(torch.tensor([ix]), num_classes=27).float()
        logits = xenc @ W
        counts = logits.exp()
        p = counts / counts.sum(1, keepdims=True)

        # 2. 按预测概率分布 p 抽样下一个字符编号
        ix = torch.multinomial(
            p, num_samples=1, replacement=True, generator=g
        ).item()
        out.append(itos[ix])

        # 3. 如果抽到了结束符 '.' (编号 0)，则当前名字生成完毕
        if ix == 0:
            break

    print(''.join(out))
